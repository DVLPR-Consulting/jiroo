| Task 10 spec review | Runtime backlog creation omitted its private scheme, Simple config, and creator administrator occupancy. | Backlog, statuses, cloned grants, config, and creator occupancy are provisioned atomically. |
| Task 10 spec review | Business mutations outside the administration surface did not record platform-admin bypass use. | `requirePermission` is the mutation boundary and records the event; read/admin-specific boundaries avoid false or duplicate events. |
| Task 10 verification | The status integration fixture expected an unseeded activity and borrowed an arbitrary actor from another parallel suite. | The expected transition is seeded and the suite owns a dedicated actor, removing the cross-suite FK race. |
| Task 10 independent review | Backlog item/admin/helper surfaces materialized the user directory without consistently requiring `browse_users`, passed email unnecessarily, and offered users who lacked `assignable_user`. | Directory reads are gated, referenced identities are projected separately, emails are removed from picker DTOs, and assignment candidates are filtered with non-auditing effective-permission decisions. |
| Task 10 independent review | Backlog-scoped administration actions exposed different errors for an absent backlog and an existing inaccessible backlog. | A common non-auditing `browse_backlog` read gate now returns the same hidden-resource result before functional authorization or domain calls. |
| Task 10 independent review | `assignable_user` was evaluated through the mutation boundary with the assignment target as actor, producing a false platform-administrator bypass event. | Target eligibility now uses `checkPermission`; only the authenticated mutation actor crosses the audited boundary. |
| Task 10 independent review | Two Playwright processes could load config before reservation and the losing JUnit reporter could overwrite the owner's final proof. | JUnit writes to a PID-scoped temporary file; an `onExit` reporter verifies lock ownership and publishes by exclusive atomic hard link. A real two-process regression proves the loser cannot replace the owner report. |
| Task 10 R2 re-review | Current assignee/reporter identities disappeared when `browse_users` was denied or the stored target was no longer assignable. | Referenced `{id,name}` identities remain separate from candidates. Inline rows use the stored `assigneeName`; detail selects render a missing current identity as a selected disabled option without adding it to the candidate set. |
| Task 10 R2 re-review | A forged permission-helper Server Action could query a user without `browse_users`. | After backlog-read and backlog/global-admin gates, the action now requires global `browse_users` before calling the helper service. |
| Task 10 R2 re-review | Assignment candidates used one complete `checkPermission` resolution per directory user. | A server-only DAL resolver loads backlog context once and resolves every candidate in one contextual SQL query. The two-query bound is independent of directory size and preserves direct, group, project-role, authenticated-user, browse-prerequisite, and platform-admin semantics. |
